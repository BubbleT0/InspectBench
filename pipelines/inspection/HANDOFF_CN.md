# U1 Image Critic V6.3 交接文档

## 1. 定位与版本

本包版本为 `6.3.0`，正式管线对应研发阶段的 V6.3-I。第一性原理是找出图中肉眼明显的 Artifact 与明显文字错误，并框出供 edit 模型一次局部重绘的独立区域。它不做通用审美评分、年份或事实知识核查，也忽略肉眼几乎不可见的小瑕疵。

V6.3-D、V6.3-H 等中间消融不属于本交付包。CLI 会自动启用正式配置，无需调用方拼装实验开关。

## 2. 输入与防泄漏

- `--input-root` 递归发现图片。
- `--input-jsonl` 可选 allowlist，默认路径字段为 `image_absolute_path`，并保持 JSONL 顺序。
- 文件名、父目录、数据集标签和参考答案不会发送给模型；模型只接收提示、结构化上下文和图片像素。
- 正式全量必须使用 `--all --confirm-run-all YES`；建议先用 `--limit-images 1` 冒烟。
- API Key 只从 `--api-key-env` 指定的环境变量读取。

## 3. 输出与成功语义

| 文件 | 作用 |
|---|---|
| `manifest.json` | 图片 ID、相对路径和读取映射 |
| `run_config.json` | 模型、版本、并发、重试及 bbox 协议 |
| `results.jsonl` | 在线整编成功并通过严格校验的正式结果 |
| `errors.jsonl` | 完整工作单元重试耗尽后的失败记录 |
| `traces.jsonl` | 请求阶段、覆盖、重试和耗时轨迹 |
| `index.html` | 由报告 CLI 生成的可视化 |

成功记录要求 `status=ok` 且包含合法 `consolidated_result`。发现阶段有输出但在线整编失败不算成功，不允许事后离线整编伪装为正式结果。复用输出目录续跑时仅跳过已成功的 `(sample_id, workflow)`，失败项会重新执行完整在线链路。

## 4. bbox 与编辑区域协议

所有 bbox 均为整数 `[x1,y1,x2,y2]`，坐标范围 `[0,1000]`，左上为 `(0,0)`、右下为 `(1000,1000)`，且 `x1<x2, y1<y2`。协议贯穿模型输入输出、业务对象、trace、JSONL、在线整编和 HTML。

同一重绘区域存在多种问题时只保留一个 bbox，在 `issues` 中合并全部问题；空间独立、需要分别重绘的实体保留多个 bbox。禁止近全图框、重复框以及大框套住已经准确定位的小框。框允许为局部重绘保留少量上下文冗余。

分类为：`rendering_artifact`、`structural_artifact`、`topology_artifact`、`relational_physical_artifact`、`text_visual_integrity`、`text_content_fidelity`。

## 5. 管线流程

1. 对整图并发执行语义分区、文字盘点、实体盘点和独立盲盘点。
2. 对文字和非文字实体分别建立覆盖账本；局部检查使用原图、上下文 crop 和无损放大 detail crop，文字另做交叉检查。
3. 双 Artifact 全图专员分别检查结构/交互和渲染/材质问题，弥补局部选择性复核的 Artifact 召回风险。
4. 稠密区域采用受约束微批；任何缺失 region ID、非法响应或覆盖缺口都拆分恢复，不能当作阴性。
5. 候选经 Skeptic 质疑和 Judge 裁决；局部明确证据优先于同区域模糊全图猜测。
6. 在线模型整编决定独立重绘区域、bbox、编辑目标和来源取舍，程序回填问题明细并执行来源守恒、中文字段、置信度、重复框与嵌套框校验。

## 6. V6.3 加速点

- 稠密局部区域以最多 4 张视觉输入组织微批，减少相同语义区域的重复请求。
- 清单和局部检查载荷压缩，但完整区域 ID、坐标和上下文仍保留。
- 在线整编使用来源原子化和组件级恢复，非法局部结果会走在线模型修复或完整在线回退，不使用离线结果替代。
- 保留 V6.0 的异步裁剪/编码缓存、覆盖恢复预取以及覆盖审计与局部检查重叠调度。

## 7. 推荐运行配置

直接使用 `examples/run_v63.sh`。CLI 自动启用 V6.3-I，对应 `coverage_mode=harness_v42`、全局请求上限 64、区域检查并发 32、Skeptic 并发 16、区域检查与质疑 batch 均为 2、输出上限 16000 token、请求超时 900 秒。

示例默认图片级并发为 `${CRITIC_MAX_IMAGES_IN_FLIGHT:-4}`，可按服务容量调整。图片并发 1 只是隔离单图延迟的实验设置，不是生产限制；提高图片并发不会删除检查步骤，但所有图片共享全局请求上限，应结合服务队列、显存与错误率调参。

## 8. 已验证结果与边界

在固定 30 张开发集、图片并发 1 的验证中，V6.3-I 为 30/30 一次在线成功，平均 31.02 秒/图、P50 28.57 秒、P90 51.50 秒、最大 73.32 秒；Artifact 命中 12/12、文字命中 15/18。最终 249 个编辑区域、652 条问题中所有 bbox 均合法，未发现重复框或嵌套框。

这些数字来自特定 27B 模型服务和小规模开发集，只用于版本回归参考，不构成完整 benchmark 精度承诺。正式接入仍需用目标模型和数据做冒烟、吞吐与失败率验收。
