# V4 覆盖完整性修复与 BBox 1000 坐标协议设计

## 背景与目标

V4 开发回归暴露的核心问题不是模型缺少基础视觉能力，而是覆盖链路允许“部分检查”伪装成“完整检查”：

- 实体/布局清单可能因退化坐标而完全失效；
- 文字清单可能只枚举部分语义区块；
- 后续多轮检查只覆盖已枚举区域，无法发现清单之外的内容；
- 覆盖审计可以在没有逐区核销证据时自行声明完整；
- 已发现少量问题时，覆盖失败不会改变最终结论，导致结果看起来完整但实际存在大面积遗漏。

本次修改同时完成两个目标：

1. 将覆盖完整性从提示词偏好升级为程序可验证的安全不变量；
2. 将当前管线所有 bbox 的标准表示统一为原图归一化整数坐标 `[0,1000]`。

第一性原理保持不变：只检查并定位肉眼明显的 Artifact 和明显文字错误，输出适合交给 edit 模型局部重绘的独立区域；不追求轻微瑕疵和美观度问题。

## 范围和兼容策略

### 新流程

新流程中，以下环节涉及的所有 bbox 坐标字段全部使用 `[x1,y1,x2,y2]`、`0<=x1<x2<=1000`、`0<=y1<y2<=1000`；该范围不适用于置信度、比例阈值、评分或其他非 bbox 数值：

- 公共 `BBox` 类型；
- 模型请求提示词与 structured-output schema；
- 内容清单、覆盖审计、区域检查、候选复核和最终整编；
- `ImageAsset`、`Region`、`Finding` 及 metadata；
- trace、结果 JSONL 和 HTML 内嵌数据；
- bbox 扩张、映射、交并比、包含和去重计算；
- 测试夹具与断言。

坐标采用整数作为协议输出。程序接收模型输出时只接受整数或值为整数的有限数值（例如 `120.0`），不静默取整、不静默裁剪；越界、非整数或退化值必须触发结构校验失败和定向重试。

### 像素裁剪边界

只有最底层图像裁剪适配器可以将 `[0,1000]` 临时换算为像素坐标：

- 左上角使用向下取整；
- 右下角使用向上取整；
- 最终裁剪范围限制在真实图像尺寸内；
- 转换值不回写到业务对象或结果文件；
- crop 产生的 `ImageAsset.bbox` 仍保存原图 `[0,1000]` 坐标。

禁止在其他模块中出现隐式 `/1000`、`*1000` 或 `[0,1]` bbox。

### 历史产物

已有 V1–V4 结果文件不批量改写，避免改变已完成的实验产物。新版 HTML 渲染器只在读取历史结果时兼容 `[0,1]`：

- 四个坐标均在 `[0,1]` 时按旧协议读取；
- 否则按 `[0,1000]` 读取；
- 混合、越界、退化或非有限值显示为无效 bbox，不猜测修复；
- 新生成的 JSONL 和 trace 只能写出 `[0,1000]`。

兼容逻辑只存在于历史结果展示层，不进入模型和业务处理路径。

## 一、分层覆盖账本

内容覆盖改为两层清单，不依赖单轮自由枚举直接证明完整：

### 第一层：版面分区

模型先根据图片可见内容划分数量自适应的语义版面区，例如：

- 主标题/页眉；
- 左侧信息面板；
- 中央图表或主体实体；
- 右侧说明卡片；
- 页脚、图例或离散标签区。

分区必须覆盖所有可见内容区域，但不要求把背景空白完整铺满。分区依据版面和语义结构产生，禁止固定 `3x3` 切图。

每个分区记录：

- `zone_id`；
- `bbox_norm`；
- `description`；
- `expected_content_kinds`，取值可包含 `text`、`entity`、`layout`；
- `coverage_state`，初始为 `pending`。

### 第二层：区内语义单元

文字与实体清单必须引用所属 `zone_id`。文字按适合一次语义检查或一次局部重绘的完整区块枚举，不能按单行、单词机械切碎；空间独立的多个标签仍需分别枚举。实体按独立实体或语义完整区块枚举。

每个 zone 最终必须得到以下一种程序可审计状态：

- `checked`：期望的内容通道均成功枚举并完成检查；
- `confirmed_empty`：独立复核确认该通道在此 zone 内确实没有相应内容；
- `failed`：清单、坐标、裁剪或检查阶段未能完成；
- `pending`：尚未核销，不能进入终态。

“某个 zone 没有返回区域”不等价于 `confirmed_empty`。

## 二、独立覆盖复核

原来的 `coverage_complete=true` 自我声明不再具有终态效力。为减少主清单与复核之间的相关性遗漏，复核分成“盲审”和“对账”两步。

### 盲审

独立调用只接收原图和覆盖任务，不接收主清单、主清单 rationale 或已有缺陷结论。它独立输出：

- 自己观察到的语义版面区；
- 每个区中是否存在文字、实体或重要版面结构；
- 特别容易漏掉的标题、标签、表格、图例、角落信息和密集文字区。

盲审不是质量判断，不输出 Artifact 结论。

### 对账

程序先将盲审清单与主清单按空间相交和语义类型对齐，再把差异项交给对账复核。对账复核接收：

- 原图；
- 第一层 zone 清单；
- 每个 zone 已枚举的文字、实体和版面单元摘要；
- 各通道的结构校验状态。

复核任务不是重新做质量判断，而是逐 zone 回答：

- 已有清单是否覆盖该 zone 中肉眼可见的主要文字、实体和版面内容；
- 是否存在漏掉的完整语义单元；
- 声称为空的通道是否确实为空。

若主清单和盲审任一方认为某 zone 存在某种内容，该 `zone_id × content_kind` 就必须进入 coverage ledger；不能由另一方的“未发现”抵消。只有双方均未观察到某类内容，并且对账复核确认确实为空时，才可标记 `confirmed_empty`。

程序按 `zone_id × expected_content_kind` 建立 coverage ledger。只有所有必需单元均为 `checked` 或经独立复核得到 `confirmed_empty`，全图覆盖状态才可为 `ok`。

复核发现漏项时，将漏项加入清单并正常执行后续检查；不能只把“可能遗漏”写进 rationale。

## 三、清单失败恢复

清单结构或 bbox 校验失败时，按以下顺序恢复：

1. 将具体错误、失败 zone 和无效 region ID 反馈给同阶段重试；
2. 重试仍失败时，仅针对失败 zone 重新建立局部清单；
3. 局部输入过小时，使用无损放大后的 crop，但模型仍输出映射到原图的 `[0,1000]` 坐标；
4. 局部结果必须通过 crop-to-full 映射、正面积及 zone 相交校验；
5. 达到重试上限后将对应 ledger 单元标为 `failed`。

其他角色偶然发现的跨职责问题仍可作为候选证据重路由，但不能据此把失败的 coverage ledger 标成完整。

## 四、终态语义

覆盖状态与缺陷结论分开保存：

- `quality_verdict`：`artifact_present`、`no_artifact` 或 `uncertain`；
- `coverage_status`：`ok`、`degraded` 或 `failed`；
- 对外 `verdict` 由两者共同决定。

规则如下：

- `coverage_status=ok` 时，允许正常输出 `artifact_present` 或 `no_artifact`；
- `coverage_status!=ok` 时，对外结论必须为 `uncertain`，无论是否已经发现部分问题；
- 已确认的问题仍保留在 `findings` 中，作为“已发现但非穷尽”的结果展示；
- metadata 必须包含失败 zone、失败通道、重试次数和 `harness_abstention_reason`；
- HTML 明确显示“覆盖不完整，以下问题不是穷尽结果”，不能只显示“发现质量问题”。

这条规则消除“发现了 11 个问题，所以结果看起来完整，但仍漏掉大面积文字”的错误语义。

## 五、BBox 1000 公共协议

### 公共类型

`BBox` 成为唯一业务坐标类型：

- `full_image()` 返回 `[0,0,1000,1000]`；
- `from_value()` 拒绝布尔值、NaN、Infinity、非整数、长度错误和越界值；
- 值为整数的浮点表示可以规范化成整数，但任何小数部分都不能被静默舍入；
- `as_list()` 始终返回四个整数；
- 提供唯一的 `to_pixel_box(width,height,padding)` 边界转换方法，或由裁剪适配器调用同一公共函数；
- 不提供静默接受 `[0,1]` 的业务兼容路径。

### Schema 与提示词

所有模型 bbox schema 统一为：

```json
{
  "type": "array",
  "items": {"type": "integer", "minimum": 0, "maximum": 1000},
  "minItems": 4,
  "maxItems": 4
}
```

提示词明确说明：

- 坐标相对于当前请求所声明的原图；
- 左上为 `[0,0]`，右下为 `[1000,1000]`；
- 必须满足严格正面积；
- 即使模型看到的是 crop，也按请求字段指定的坐标空间返回，不允许自行切换为 crop-local 坐标。

### 几何阈值迁移

所有依赖坐标绝对差值的阈值乘以 `1000`，比例性质不变：

- 全图框边缘容差；
- bbox padding；
- 最小宽高；
- tile/crop 映射；
- 近似相等判断。

IoU、覆盖率、面积比例和包含率为无量纲量，公式及阈值保持不变。

## 六、HTML 展示

新版结果的前端百分比换算统一为：

```text
left = x1 / 10 %
top = y1 / 10 %
width = (x2 - x1) / 10 %
height = (y2 - y1) / 10 %
```

历史结果由只读适配函数转换为同一展示尺度。页面同时展示：

- 最终 bbox 序号；
- `[0,1000]` 坐标；
- `coverage_status`；
- 未覆盖 zone 和失败原因；
- 已发现问题是否为非穷尽结果。

## 七、测试策略

实现遵循测试先行，至少覆盖：

### 坐标协议

- `BBox` 接受边界内整数并拒绝退化、越界、非有限和旧 `[0,1]` 小数输入；
- `full_image()` 为 `[0,0,1000,1000]`；
- bbox 扩张、交并比、嵌套、去重和 tile-to-full 映射结果正确；
- Pillow 裁剪使用正确的 floor/ceil 像素边界；
- 所有 structured-output schema 的最大值为 `1000` 且类型为整数；
- trace、JSONL 与整编结果不存在 `[0,1]` bbox；
- HTML 对新 `[0,1000]` 和历史 `[0,1]` 均能正确叠框。

### 覆盖完整性

- 一个清单通道完全退化时，即使已发现部分问题，最终也必须为 `uncertain`；
- zone 内没有返回文字区域时，必须经独立空区复核才能核销；
- 盲审在不接触主清单的情况下发现的文字或实体区必须进入 coverage ledger；
- 主清单与盲审不一致时不能以任一方的空结论直接核销；
- audit 声称完整但 ledger 存在 `pending/failed` 时，程序拒绝 `coverage_complete`；
- 复核发现漏项后，漏项会进入正常检查；
- 失败 zone 可以单独重建并映射回原图；
- 跨角色候选不能替代失败 coverage ledger；
- `coverage_status=ok` 是输出 `no_artifact` 的必要条件；
- HTML 对部分结果显示非穷尽警告。

### 回归样本

使用已知开发样本验证机制，不写入样本 ID、特定文字或固定 bbox：

- 密集文字图片不能因只枚举部分文字块而得到完整覆盖；
- 某一清单通道坐标全部退化时，不能隐藏覆盖失败；
- 大框套多个小框的既有整编约束继续生效；
- V1–V4 历史 HTML 数据仍可查看，历史 JSONL 不被修改。

## 八、迁移顺序与失败隔离

实现按以下边界推进：

1. 先迁移并测试公共 `BBox`、几何函数和 Pillow 裁剪；
2. 再迁移模型 schema、提示词和所有业务模块；
3. 增加 zone coverage ledger、独立复核及局部恢复；
4. 修改终态合成和 HTML；
5. 运行全量单元测试与静态 bbox 协议扫描；
6. 只在开发回归样本上测试，不直接运行完整图片集。

在全部代码迁移完成前，不允许运行真实模型，避免半套 `[0,1]`、半套 `[0,1000]` 的结果进入实验目录。

## 验收标准

- 新流程任何持久化、模型交互和业务 trace 中都不存在 `[0,1]` bbox；
- `[0,1]` 只允许存在于历史展示兼容测试数据，不进入新业务流程；
- 只有像素裁剪边界执行一次明确的 `[0,1000] → pixel` 转换；
- 覆盖 ledger 未全部核销时，无论发现多少问题，最终对外结论都是 `uncertain`；
- 已发现问题在覆盖失败时仍保留，并明确标记为非穷尽；
- 漏项复核按 zone 工作，不退回固定网格，也不把文字机械切成行或词；
- 所有自动化测试通过后，只运行少量开发回归样本并生成独立 HTML，等待人工审核。
