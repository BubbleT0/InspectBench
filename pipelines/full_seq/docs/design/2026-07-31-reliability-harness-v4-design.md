# Adversarial Consensus V4：可靠性 Harness 设计

## 目标

V4 不继续针对图片内容增加识别提示词，而是将现有模型视为“基础视觉能力足够、单次调用和结构化控制不稳定”的组件，通过程序化 harness 稳定完整管线。

第一性原理仍是找出肉眼明显的 Artifact 和明显文字错误，并输出适合局部重绘的独立区域。V4 不包含样本 ID、目录标签、具体文案、固定坐标或场景特例；V3 的代码路径、结果和 HTML 保持冻结。

## Harness 边界

Harness 只负责控制和验证，不替模型创造诊断：

- 验证每个阶段的结构与语义不变量；
- 将具体校验错误反馈给同一阶段，进行最多两次定向重试；
- 将模型已观察到但进入错误职责通道的证据重新送入正常复核链；
- 对关键文字区域的负结论执行一次独立复核；
- 无法证明覆盖完整时返回 `uncertain`，禁止伪装成 `no_artifact`；
- 保存每次重试、拒绝、重路由和降级的可审计轨迹。

## 1. 内容清单契约

文字清单和实体清单的原始结果必须同时满足：

- `regions` 是非空数组；
- 每个 bbox 均为原图归一化坐标，且 `x2>x1`、`y2>y1`；
- 不允许全部区域退化、全部被规范化丢弃或以整图占位代替内容枚举；
- 原始区域中有效区域比例不得低于 50%。

不满足时，harness 不沿用普通网络重试，而是向模型返回具体语义错误，例如退化 bbox 的区域 ID、有效/无效数量以及坐标要求，要求重新提交完整清单。最多重试两次，并选择有效区域数最多、有效率最高的结果。

若文字和实体两个通道最终都无法提供有效区域，则内容覆盖状态为 `failed`；若仅部分通道恢复，则为 `degraded`。两者都不能直接产生 `no_artifact`。

## 2. 文字负结论复核

每个完整文字语义单元继续执行 `Text Visual` 与 `Text Fidelity`。其中 `Text Visual` 返回无问题时，harness 追加一次独立的 `Text Visual Negative Verification`：

- 使用新的调用和独立提示，不引用首轮结论；
- 重新逐字扫描完整语义单元；
- 仍只接受直接可见、major/critical、置信度严格大于 0.6 的错误；
- 两轮任意一轮发现有效问题，即进入既有 skeptic 与 grounding 复核；
- 两轮均为有效负结论，才允许该区域通过文字视觉检查。

该机制只降低随机漏判，不改变问题定义或置信度门槛。

## 3. 跨角色证据重路由

非文字整图角色偶尔会发现明显文字错误。V3 会因职责边界直接丢弃这些 finding；V4 不直接采纳，也不静默丢弃，而是：

1. 标记为 `rerouted_text_evidence`；
2. 保留模型给出的原始 bbox、观察、置信度和来源角色；
3. 送入既有 skeptic、grounding 和 judge 链；
4. 只有通过全部既有核心质量门槛后才成为最终 finding。

这样职责边界仍然存在，但不会丢失模型已经看到的直接像素证据。

## 4. 终态安全不变量

只有以下条件同时满足时才能输出 `no_artifact`：

- 内容覆盖状态为 `ok`；
- 所有关键阶段均有合法结构化输出；
- 没有待复核的高置信度观察；
- 所有角色均给出有效的负结论；
- judge 没有出现“判断有问题但候选为空”的矛盾状态。

若角色判断 `artifact_present` 或 `uncertain`，但最终没有可接受候选，V4 输出 `uncertain` 并记录 `harness_abstention_reason`。Harness 不制造 bbox，也不把不完整证据强行升级成问题。

## 5. 局部重绘区域拓扑契约

最终 edit region 除了不能重复，还必须满足嵌套关系约束：

- 若一个大框包含两个或更多已经独立、准确定位的小框，大框和这些小框不得同时保留。
- 该约束依据框之间的相对包含关系，而不是绝对面积上限；主要实体本身有问题时仍可使用较大框。
- 整编阶段必须按“一次局部重绘如何执行”二选一：若多个小区域应分别重绘，保留小框并删除冗余容器框；若整个主体确需一次整体重绘，则合并问题到主体框并删除内部小框。
- 大框存在未被小框覆盖的独立问题时，需要为该独立编辑目标重新定位，不能继续使用包住所有小框的聚合框。
- 初次整编违反嵌套契约时触发带具体 region ID 的修复；修复后仍违反则整编失败，禁止把不合适的框交付给 edit 模型。

## 6. 实验协议

- 现有 30 张图片已被用于多轮观察，只作为 V4 开发回归集。
- V4 先用合成结构化响应测试验证控制逻辑，再在这 30 张上做带明确标识的回归运行。
- 正式比较 V3/V4 稳定性时，另取未被人工查看的新 holdout；在运行前冻结代码、配置和阈值。
- 同一冻结版本至少重复运行两次，统计结论一致率、区域召回一致率、结构化失败率、harness 重试率和安全弃权率。
- V4 使用独立输出目录与 HTML，不覆盖 V2/V3。

## 验收标准

- 退化清单坐标会触发带错误反馈的语义重试。
- 清单完全失效时不会执行零次区域检查后返回 `no_artifact`。
- 非文字角色发现的文字问题会进入正常证据复核链，而不是直接采纳或静默丢弃。
- 文字视觉负结论有独立复核轨迹。
- `artifact_present + 0 candidates`、覆盖失败或关键阶段矛盾均安全降级为 `uncertain`。
- 大框套住多个独立小框的结果不能通过 V4 最终整编校验。
- 所有 harness 行为在 trace 和结果 metadata 中可见。
- V3 行为和已有输出保持不变。
