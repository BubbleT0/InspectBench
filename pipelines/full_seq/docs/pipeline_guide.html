从整图理解，到可执行的局部重绘区域

V4.1 不是一次问答式的“看图找错”。它先建立内容覆盖账本，再让文字与非文字 Artifact 独立审查，使用原图、上下文与无损放大细节交叉确认，最后只把证据充分、肉眼明显、可局部重绘的问题整编为最终区域。

中文推理与描述BBox 整数 [0,1000]文字 / Artifact 独立核销只接受明显核心错误正式结果禁止离线补救

第一性原理

所有环节都服务于同一个交付目标，而不是追求“问题越多越好”。

01
找出明显的 Artifact 与明显的文字错误，并框出适合 edit 模型一次局部重绘的区域。

框可以保留少量上下文冗余；实体或语义区块的独立性比绝对面积更重要。一个区域有多种问题时只保留一个框，在描述中完整列出所有问题。

01

纯像素输入

读取图片，不把目录名、类别标签等答案线索发给模型。

02

覆盖建模

双路语义分区，列出文字与实体，建立可核销账本。

03

多尺度检查

原图、上下文、无损放大细节共同确认问题。

04

对抗复核

Proposer → Skeptic → Judge，过滤误报与弱证据。

05

在线整编

合并同一重绘目标，拆开空间独立目标，消除嵌套重复。

06

结构化输出

正式结果、覆盖状态、编辑区域、来源闭环与完整 trace。

先保证“看全”，再讨论“判对”

V4.1 用代码维护覆盖状态，不允许模型一句“检查完了”代替可审计的覆盖证明。

① 双路语义分区

content.zones.primary 给出主布局；content.coverage.blind_inventory 独立盲查。两者取并集，任何一路的“未发现”都不能抵消另一路发现的内容。

② 内容清单与漏项审计

分别盘点文字单元与独立实体/版面区块，再由独立 coverage audit 查漏；失效的 zone/channel 会触发定向 recovery。

文

Text channel

  • 覆盖所有“被设计为可读”的文字语义单元
  • 包括标题、标签、角落小字、密集小字、伪文字
  • 检查乱码、扭曲、断裂、粘连与可直接验证的内部错误
  • 不依赖正确文案或外部知识补全

  • 正常透视、遮挡、景深与轻微 AI 瑕疵不报
  • 纯文字区域不会在本通道重复补充

程序固定三视图，避免切图制造假问题

双确认硬门槛
若模型报告问题，必须同时返回 confirmed_in_original=true 与 confirmed_in_context=true；否则代码直接把候选改为无问题。
裁剪边界规则
断头词、半行文字、孤立数字、边缘残片不能仅因 crop 截断而被认作缺陷。
区域粒度
按可独立理解和一次重绘的语义单元检查，不固定 3×3，不把一行或几个词机械切碎。

Adversarial Consensus：发现、质疑、裁决

同一个模型承担不同角色，但每一步拿到的任务、证据和输出约束不同；harness 用结构化状态约束其行为。

Proposer

多角色提出候选

结构/拓扑、关系/物理、渲染、文字覆盖四类角色并行提出候选。文字型发现即使来自 Artifact 角色，也会被重新路由到文字证据链。

Judge 不能新造问题，只能选择已有、被支持的候选。角色说“有问题”但未形成有效候选时，结果保持 uncertain，不能错误降为 no_artifact。

在线整编：从 findings 变成 edit regions

整编是正式 pipeline 内的一部分，不是跑完后人工或离线修结果。整编不新增诊断，只解决编辑目标划分与来源闭环。

目标：独立、可重绘、略有冗余

同一实体上的多个问题合进一个框与一组 issues；空间独立的实体分别保留。框覆盖完整编辑目标和必要上下文。

分层分批

来源 finding 超过 10 条时先按空间/语义分批整编，再进行全图合并校验，降低 27B 模型一次处理过长列表的不稳定性。

严格来源闭环

每个 source_finding_id 必须恰好进入一个 region，或被 discard 且提供中文原因；禁止未知来源 ID。

程序校验

校验合法 bbox、明显性门槛、重复/嵌套、来源重复或遗漏；失败会进入在线 repair，而不是悄悄输出坏结果。

当前问题分类

最终只聚焦两大域、六个可执行类别。

D1 · Artifact

非文字图像错误

rendering_artifact局部融化、边界破碎、重复纹理、材质/光照不连续
structural_artifact解剖或物体形态错误、部件缺失/重复、数量比例异常
topology_artifact错误融合、穿插、断裂、连接或遮挡顺序异常
relational_physical_artifact交互、支撑、重力、尺度、空间关系、阴影反射异常

D2 · Text Correctness

文字正确性

text_visual_integrity乱码、伪文字、字形断裂/粘连/扭曲、缺笔、多笔、不可辨认
text_content_fidelity仅限图内能直接验证的明显漏字、多字、拼写或格式矛盾

BBox 协议与正式输出

只有 bbox 坐标使用整数 [0,1000]；不是把所有数值字段都归一化。所有阶段统一同一坐标语义。

坐标规范

[x1, y1, x2, y2]，左上角是 (0,0)，右下角是 (1000,1000)。模型输入输出、业务对象、trace、JSONL、整编与 HTML 均持久化为整数坐标。

重试、保守退出与正式失败

目标是让 pipeline 自己完成链路；失败不能靠事后离线整编伪装成成功。

单次模型请求：初次 + 2 次重试→在线整编：初次 + 2 次重试→完整工作单元：初次 + 2 次重跑→仍失败则写 errors.jsonl

Coverage degraded / failed

已发现的问题仍保留，但整体 verdict 降为 uncertain，置信度不高于 0.5，并标记 findings_non_exhaustive=true。

在线整编 repair

批内校验失败进入 consolidate_repair；分批合并冲突进入 consolidate_global_repair。repair 仍必须遵守来源闭环。

Formal failure

JSON/服务/整编校验在所有重试后仍失败，整张图记为 error，不生成貌似完成的正式 edit regions。

为什么不允许离线补结果？

离线整编只能帮助临时人工审查，无法证明正式 pipeline 可以稳定走完全链路。V4.1 的成功定义是在线审查、裁决、整编、程序校验全部完成。

可在 trace 中看到的主要阶段

展开查看模型调用与代码责任边界。英文 stage 名保留，便于直接对照 JSONL trace。

1. 语义区与内容盘点
  1. content.zones.primary：主语义布局区。
  2. content.coverage.blind_inventory：独立盲查分区。
  3. content.inventory.text / content.inventory.entity：双类内容清单；无内容须明确 confirmed_empty。
  4. content.coverage.audit.text / .artifact：独立查漏。
  5. content.inventory.zone_recovery：定向恢复未核销的 zone/channel。
2. 局部取证与候选形成
  1. content.inspect.multiscale：原图、上下文、细节三视图检查。
  2. consensus.propose：Artifact 专家角色提出补充候选。
  3. 代码统一候选 ID、bbox 与明显性字段，并把文字候选路由到文字证据链。
3. 对抗共识
  1. consensus.challenge：Skeptic 基于真实 crop 逐条反证。
  2. consensus.judge：Judge 仅接纳已有且有支持证据的候选。
  3. 代码应用 coverage gate：覆盖不完整时保持 uncertain，避免假阴性。
4. 在线结果整编
  1. consensus.consolidate：按一次局部重绘目标整编。
  2. consensus.consolidate_repair：修复批内校验错误。
  3. consensus.consolidate_global_repair：修复分批合并后的重复、嵌套与来源闭环问题。
  4. 最终代码校验不过则正式失败，不静默降级。
